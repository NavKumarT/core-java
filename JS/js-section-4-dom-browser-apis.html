1. Understanding the DOM, BOM and window

  • DOM (Document Object Model): the browser's in-memory, object representation of an HTML/XML document, plus the API (document.getElementById, createElement, events) that lets JavaScript read and change structure, content and style. It is a language-neutral W3C/WHATWG standard, not part of JavaScript itself.
  • DOM tree: the document is parsed into a hierarchy of nodes: document at the root, then <html>, with <head> and <body> as children, and so on. Each tag is an element node; text, comments and attributes are nodes too. Every node has a parent (except the root), and siblings.
  • DOM manipulation: using the API to create, read, update, delete or move nodes, change attributes, classes and styles, and react to events, so the page updates without reloading.
  • BOM (Browser Object Model): objects that expose the browser itself rather than the page: window, navigator, location, history, screen, timers, alert/confirm/prompt, localStorage, fetch. It has no formal standard (parts are in HTML spec) but is consistent across browsers.

What is the DOM / DOM API? What is a DOM tree? What is DOM manipulation?

See the bullets above: the object model of the page, its programming interface, the tree of nodes it forms, and changing that tree from JavaScript.

Difference between window and document?

window is the global object representing the browser window and everything global (BOM); document is one of its properties and represents the loaded page content (DOM). Everything you declare globally lives on window; you reach HTML elements through document.

Difference between DOM and BOM? Which is the global object in the browser?

DOM manages page content (structure, styles, events); BOM talks to the browser (URL, history, screen, navigator, timers). The global object is window (also reachable as self or globalThis); in a worker it is self, in Node it is globalThis/global.

How do you get the window width/height and the address-bar value?

window.innerWidth / innerHeight (viewport) and location.href for the full URL, location.hostname for the host. Typed text in the address bar before navigation is not accessible to scripts.

  • Delay is a minimum, not a guarantee: the callback waits in the task queue until the call stack is free.
  • Both are window methods (WindowOrWorkerGlobalScope), not part of the DOM document. Because window is the global object, you can call them without a prefix: setTimeout() equals window.setTimeout().
  • For animation use requestAnimationFrame. Background tabs throttle timers (often to 1 per second or less), so don't rely on interval counting for accurate time; compute from Date.now().

Trap: for (var i=0;i<3;i++) setTimeout(()=>console.log(i),0) prints 3,3,3 (use let). setTimeout(fn(), 1000) calls fn immediately and schedules its return value. In React, always clear timers in the useEffect cleanup.
Difference between setTimeout() and setInterval()?

setTimeout schedules one execution after a delay; setInterval schedules repeated executions at a fixed period until cleared.

Why can't we write document.setTimeout() or document.setInterval()?

They are methods of window, not of document. document has no such property in its prototype chain, so it throws TypeError: document.setTimeout is not a function.

How do you stop a timer? How do you create a digital clock?

Keep the id returned by setTimeout/setInterval and pass it to clearTimeout/clearInterval. Clock: an interval of 1000 ms that writes new Date().toLocaleTimeString() into an element (code above).

How would you implement setInterval using setTimeout?

Recursive setTimeout: const run = () => { fn(); id = setTimeout(run, ms) }, which guarantees the next run starts only after the previous finishes.

3. Event bubbling and capturing (propagation)

When an event fires on an element it travels in three phases: 1. Capturing (window → document → html → ... → parent of target), 2. Target, 3. Bubbling (target → parent → ... → document → window).

  • Bubbling: the event propagates from the innermost element up to its ancestors, triggering their handlers. Capturing: the reverse, from outermost ancestor down to the target.
  • Default: listeners run in the bubbling phase (third argument false).
  • Change path to capturing: addEventListener("click", fn, true) or { capture: true }. (Inline onclick and el.onclick can only bubble.)
  • Stop: event.stopPropagation() stops it moving to further elements; stopImmediatePropagation() also blocks other listeners on the same element. preventDefault() is different: it cancels the browser action (link navigation, form submit) but doesn't stop propagation.
  • Element that fired it: event.target (the deepest element actually clicked). event.currentTarget (or this in a regular function) is the element whose listener is running.
<div id="d1"><div id="d2"><div id="d3">Click me</div></div></div>

const log = id => () => console.log(id);
d1.addEventListener("click", log("d1"));
d2.addEventListener("click", log("d2"));
d3.addEventListener("click", log("d3"));
// click d3: d3, d2, d1                  (bubbling: inside out)

// Practical question variant: add capture to d1 only
d1.addEventListener("click", log("d1"), true);
// click d3: d1 (capture phase first), d3, d2     (d1's capture listener already ran)

d2.addEventListener("click", e => { e.stopPropagation(); console.log("d2") });
// click d3: d3, d2 and d1 never fires in bubbling

list.addEventListener("click", function (e) {
  console.log(e.target.id, e.currentTarget.id, this === e.currentTarget);   // clicked child vs listener owner
});
Trap: not every event bubbles: focus, blur, mouseenter, mouseleave, load, unload, scroll (on elements) do not. focusin/focusout are the bubbling versions. Two listeners with the same function and same capture flag on one element are added only once. removeEventListener must receive the same function reference and capture flag. Calling stopPropagation in a high-level handler can break analytics or UI libraries that rely on document-level listeners.
What is event bubbling and capturing? Default path?

Events travel down from the root to the target (capturing) and then back up (bubbling). Default handlers run on the way up, i.e. bubbling.

How do you stop propagation? How do you change the default path?

event.stopPropagation() (and stopImmediatePropagation()). Register with addEventListener(type, fn, true) or {capture:true} to listen during capturing.

How do you get the element on which the event fired? Output of the nested-div code?

event.target. The output is inner to outer on bubbling (d3, d2, d1) and outer to inner for capture listeners; see the examples above.

target vs currentTarget vs relatedTarget?

target: origin of the event; currentTarget: element the handler is attached to (changes during propagation); relatedTarget: the other element in focus/mouseover/mouseout pairs.

4. Event delegation

Attach one listener to a common ancestor and use bubbling plus event.target to figure out which child triggered it, instead of attaching a listener to every child.

// <ul id="list"><li data-id="1">A <button class="del">x</button></li>...</ul>
list.addEventListener("click", (e) => {
  if (e.target.tagName === "LI") console.log("li", e.target.textContent);      // tagName is UPPERCASE in HTML
  if (e.target.nodeName === "BUTTON") {}                                       // same idea
  const btn = e.target.closest("button.del");                                  // robust: handles clicks on child icons
  if (btn && list.contains(btn)) btn.closest("li").remove();
  const id = e.target.closest("li")?.dataset.id;                               // data-id attribute
  if (e.target.matches("input[type=checkbox]")) console.log(e.target.checked);
  if (e.target.value !== undefined) console.log(e.target.value);              // value of the element that raised the event
});
list.append(document.createElement("li"));   // new items work automatically, no new listener
  • Why useful: fewer listeners (memory/performance), works for elements added later (dynamic lists, tables, menus), cleaner setup/teardown. Frameworks use it internally (React attaches handlers at the root).
  • Element type check: e.target.tagName/nodeName (uppercase for HTML), e.target.matches(selector), e.target.classList.contains(), e.target.closest().
  • Value of the element: e.target.value (inputs/select/textarea), .checked, .textContent, .dataset.x, .getAttribute().
Trap: if a button contains <span> or <img>, e.target is the inner node, so tagName === "BUTTON" fails; use closest(). Delegation doesn't work for events that don't bubble (use focusin instead of focus, or capture). If a child calls stopPropagation, the delegate never sees the event.
What is event delegation and how is bubbling useful practically?

Handling child events at a parent through bubbling. It reduces listeners, supports dynamically added elements, and centralises logic for lists, menus, tables and forms.

Which property checks the element type, and how do you get its value?

event.target.tagName / nodeName (or matches) for type; event.target.value for the value.

What is a node? Types of nodes?

Everything in the DOM tree is a node: element, text, attribute, comment, document, doctype, fragment nodes, differentiated by nodeType. Elements are the subset that correspond to tags.

How do you access the next same-level element? childNodes vs children?

el.nextElementSibling (or nextSibling including text). childNodes returns every child node including text and comments; children returns only element children.

How do you check whether an element has child nodes? What's the purpose of navigation?

el.hasChildNodes() (any node) or el.children.length/childElementCount (elements only). Navigation lets you work relative to a known element without extra queries.

Can you use document.getElementById() and element.getElementById()?

Only document.getElementById(). The method is defined on Document, not Element, because ids are unique per document. Use element.querySelector("#id") to search inside an element.

What does getElementsByTagName() return?

A live HTMLCollection of matching elements (empty collection, not null, if none).

Difference between getElementsByClassName and getElementsByName?

ClassName matches the class attribute and is available on document and elements, returning an HTMLCollection. Name matches the name attribute (form fields) and exists only on document, returning a NodeList. Both are live.

querySelector vs querySelectorAll? Searching with pseudo-classes?

First matching element or null, versus a static NodeList of all matches (empty if none). Any CSS selector works: :checked, :first-child, :nth-child(), :not(), :disabled.

Which is better: getElementBy* or querySelector*?

getElementById is marginally fastest and clearest for ids; getElementsBy* are live and fast for simple lookups; querySelector* are the most flexible (any CSS selector, consistent API) and usually good enough. Choose by need: flexibility vs live collection vs micro-performance.

How do you add 1000 items efficiently?

Build them in a DocumentFragment (or a joined string once) and append once, minimising reflows.

8. Event basics

Ways to attach an event

<!-- 1. Inline HTML attribute (avoid: mixes markup and logic, global scope, CSP issues) -->
<button onclick="save(event)">Save</button>

// 2. DOM property (only ONE handler per event; assigning again overwrites)
btn.onclick = function (e) { };
btn.onclick = null;                      // remove

// 3. addEventListener (recommended: multiple handlers, options, capture)
function onClick(e) { }
btn.addEventListener("click", onClick);
btn.removeEventListener("click", onClick);       // needs the SAME function reference

// syntax: target.addEventListener(type, listener, options | useCapture)
btn.addEventListener("click", onClick, {
  capture: false,   // listen in capturing phase if true
  once: true,       // auto-remove after first run
  passive: true,    // promise not to call preventDefault (smoother scroll/touch)
  signal: ctrl.signal   // AbortController: ctrl.abort() removes the listener
});
btn.addEventListener("click", { handleEvent(e) { /* object listener */ } });

The event object

btn.addEventListener("click", (e) => {
  e.type;              // "click"
  e.target;            // element that triggered it       e.currentTarget  // element with the listener
  e.preventDefault();  // cancel default action (link, submit, contextmenu)
  e.stopPropagation(); // stop bubbling/capturing
  e.bubbles, e.cancelable, e.defaultPrevented, e.eventPhase;   // 1 capture, 2 target, 3 bubble
  e.timeStamp, e.isTrusted;   // isTrusted false for synthetic events
  e.composedPath();           // array of the propagation path
});
btn.dispatchEvent(new CustomEvent("saved", { detail: { id: 1 }, bubbles: true }));   // custom events
btn.addEventListener("click", () => this);   // arrow: this is NOT the element; use e.currentTarget
Trap: addEventListener("click", fn()) calls fn immediately. Anonymous or inline-arrow listeners can't be removed later. el.onclick = a; el.onclick = b keeps only b. passive: true makes preventDefault() a no-op (warning). In inline onclick="foo()" foo must be global.
Various ways to configure an event with HTML elements? addEventListener syntax? What is the event object?

Inline attribute, DOM property, and addEventListener (best). Syntax: addEventListener(type, handler, options). The event object is passed to the handler and describes what happened (type, target, coordinates, keys) and provides control methods (preventDefault, stopPropagation).

preventDefault vs stopPropagation vs return false?

preventDefault cancels the browser's default action; stopPropagation stops the event travelling further; return false in an inline/DOM-property handler does preventDefault only (jQuery's version also stops propagation). In addEventListener, return value is ignored.

Condition to check Ctrl on Windows and Cmd on Mac?

if (e.ctrlKey || e.metaKey). Cmd maps to metaKey on Mac; Ctrl maps to ctrlKey.

11. Keyboard events

  • Order: keydown (repeats while held; e.repeat) → keypress (deprecated, only character keys) → keyup. Use keydown/keyup.
  • event.key: the value produced, depends on layout, Shift and CapsLock: "a", "A", "Enter", "ArrowUp", " ", "Escape".
  • event.code: the physical key, independent of layout and modifiers: "KeyA", "Digit1", "Enter", "ShiftLeft", "Space", "ArrowUp", "Numpad1". Good for games (WASD works on any layout).
  • keyCode/which/charCode: deprecated.
document.addEventListener("keydown", (e) => {
  if (e.ctrlKey && e.key.toLowerCase() === "z") { /* undo */ }       // Ctrl+Z (Shift makes key "Z", so lowercase it)
  if ((e.ctrlKey || e.metaKey) && e.code === "KeyZ") { e.preventDefault(); } // cross-platform, layout-independent
  if (e.ctrlKey && e.shiftKey && e.key === "Z") { /* redo */ }
  if (e.key === "Escape") closeModal();
  if (e.key === "Enter" && !e.isComposing) submit();              // ignore IME composition
});
// Alt+Shift key: e.key can be a symbol (macOS Option changes key), so prefer e.code for shortcuts
Trap: with Shift held, e.key is uppercase "Z", but e.code stays "KeyZ". On AZERTY, the physical "Q" key has code "KeyQ" but key "a". Browser shortcuts can't always be blocked. Don't use keypress; keydown doesn't give final input value (use input event).
How do you check if Ctrl and Z are pressed? What does event.code return? code vs key?

e.ctrlKey && e.key.toLowerCase() === "z" (or e.code === "KeyZ"). event.code returns the physical key identifier like "KeyZ". event.key returns the character/meaning of the key under the current layout and modifiers; code ignores layout.

// select (drop down): change is the event to use

  sel.selectedIndex;                                 // 0-based index
  sel.options[sel.selectedIndex].text;               // visible TEXT of the selected item
  sel.selectedOptions[0].text;                       // same; selectedOptions supports multiple select
  [...sel.selectedOptions].map(o => o.value);        // multiple select values
});

Trap: a text input's change doesn't fire while typing, and not at all if you blur without altering. keyup misses paste/mouse changes and IME input; input is the reliable one. sel.value returns the option's value, not its label. click on a checkbox also fires from label clicks and keyboard Space, and fires before/after state depending on handler order, so use change. For disabled inputs events don't fire.
onblur vs onchange?

blur fires every time the element loses focus; change fires only if its value changed since it gained focus (and is committed). Blur is for validation on exit; change for reacting to modifications.

How do you handle checkbox and radio events?

Use change and read e.target.checked (checkbox) or e.target.value (radio, firing only for the newly selected). click also works but is less semantically precise.

Differentiate onkeypress, onkeyup and oninput.

keypress: deprecated, fires for character keys before the value updates. keyup: after the key is released, value already updated, but only for keyboard. input: fires on any value change from any source (keyboard, paste, voice, drag), so it is preferred.

Which event with select, and how do you get the text of the selected item?

change. Text: sel.options[sel.selectedIndex].text or sel.selectedOptions[0].text; value: sel.value.

13. cut, copy and paste events

// fire on the focused element (or selection) and bubble; are cancelable
input.addEventListener("copy",  e => { e.preventDefault(); e.clipboardData.setData("text/plain", "custom text"); });
input.addEventListener("cut",   e => e.preventDefault());       // block cut (and the change)
input.addEventListener("paste", e => {
  const text = e.clipboardData.getData("text");           // read what is being pasted
  e.preventDefault();                                      // stop pasting
  input.value += text.trim();                              // custom handling (sanitise, format)
});
// inline: <input oncut="return false" oncopy="return false" onpaste="return false">
// disable for a whole page: document.addEventListener("copy", e => e.preventDefault());

// Async Clipboard API (secure context HTTPS, user gesture, permission)
await navigator.clipboard.writeText("copied!");
const t = await navigator.clipboard.readText();          // prompts for permission
// legacy: document.execCommand("copy") deprecated
// CSS to stop selecting: user-select: none;
  • Event order for copy/cut/paste: handler runs, then (if not prevented) the browser performs the action. cut also removes the selection and then fires input.
  • Uses: sanitise pasted text, strip formatting, limit length, confirm password fields, add attribution on copy, custom "copy to clipboard" buttons.
Trap: blocking copy/paste doesn't protect data and harms accessibility and password managers. e.clipboardData exists only inside the event; after an await it is empty. readText() requires permission and focus.
Explain cut, copy and paste events. How do you stop them?

They fire when the user cuts, copies or pastes via keyboard, menu or context menu; the event has clipboardData. Stop with event.preventDefault() in a listener (or return false in the inline attribute).

DOMContentLoaded vs loadDOMContentLoaded: HTML parsed and DOM ready (no waiting for images/styles). load (window): everything including images, iframes finished.
script, async, deferPlain: blocks parsing. async: downloads in parallel, runs as soon as ready (order not guaranteed). defer: downloads in parallel, runs after parsing, in order, before DOMContentLoaded. Modules are deferred by default.

Virtual DOMA lightweight JS copy of the UI that React diffs against the previous version to apply minimal real-DOM updates (covered in the React sections).
