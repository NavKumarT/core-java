1. Object literal

An object is a collection of key: value pairs (properties). An object literal is the { ... } syntax that creates one directly. Keys are strings or Symbols (numbers are converted to strings); values can be anything, including functions (methods).

const user = {
  name: "Asha", age: 30,
  "full-name": "Asha K",            // quotes needed for non-identifier keys
  address: { city: "Hyderabad" },
  greet() { return `Hi ${this.name}` },   // method shorthand
  get initial() { return this.name[0] }   // accessor
};
user.name; user["full-name"];       // dot vs bracket access
user.address?.city;                 // optional chaining
user.zip = 500001; delete user.zip; // add / delete
"name" in user;                     // true (includes inherited)
Object.hasOwn(user, "name");        // true (own only; prefer over hasOwnProperty)

Dynamic (computed) keys

const field = "score", i = 1;
const o = { [field]: 90, ["id_" + i]: 7, [`${field}Max`]: 100 };  // {score:90, id_1:7, scoreMax:100}
const o2 = {}; o2[field] = 5;                // bracket assignment also dynamic

Property value shorthand

const name = "Asha", age = 30;
const p = { name, age };           // same as { name: name, age: age }
const makeUser = (id, role) => ({ id, role, active: true });

Read-only properties

const cfg = {};
Object.defineProperty(cfg, "API", { value: "v1", writable: false, enumerable: true, configurable: false });
cfg.API = "v2";           // silently ignored (TypeError in strict mode / modules)
const g = { get id() { return 42 } };   // getter without setter = read-only
const f = Object.freeze({ a: 1, nested: { b: 2 } });
f.a = 9;                  // ignored; f.nested.b = 5 still works (freeze is SHALLOW)
Object.isFrozen(f);       // true
Object.seal(o);           // cannot add/delete, can still edit values
Object.preventExtensions(o); // cannot add, can delete/edit
Object.getOwnPropertyDescriptor(cfg, "API"); // {value:"v1", writable:false, enumerable:true, configurable:false}

Reference vs copy (course question)

let obj = { a: "First" };

obj1.a = "Second";
console.log(obj.a);      // "Second": both variables point to the same object in the heap

Cloning

const c1 = { ...obj };               // shallow (own enumerable props)
const c2 = Object.assign({}, obj);   // shallow (triggers setters on target)
const c3 = structuredClone(obj);     // DEEP: handles Date, Map, Set, cycles; throws on functions
const c4 = JSON.parse(JSON.stringify(obj)); // deep but loses undefined, functions, Date (becomes string), Infinity/NaN (null), Map/Set
// shallow trap
const s = { n: { v: 1 } }, t = { ...s }; t.n.v = 99; s.n.v;  // 99, nested object is shared
// full clone including prototype and accessors
Object.create(Object.getPrototypeOf(s), Object.getOwnPropertyDescriptors(s));

Useful object utilities

Object.keys(o); Object.values(o); Object.entries(o);        // own enumerable, arrays
Object.fromEntries([["a",1],["b",2]]);                      // {a:1,b:2}
Object.assign(target, src1, src2);                          // merge (mutates target)
const merged = { ...a, ...b };                              // later keys win
Object.entries(o).map(([k, v]) => [k, v * 2]);              // transform values
Object.is(NaN, NaN);                                        // true
Object.keys({ b: 1, 2: 1, 1: 1, a: 1 });                    // ["1","2","b","a"] integer keys first ascending
Traps: obj[{}] uses the key "[object Object]", so two different object keys collide (this is why Map exists). delete returns true even when the key was missing. for...in also visits inherited enumerable props, so guard with Object.hasOwn. typeof null is "object". Comparing objects with == or === compares references; for content compare use a deep-equal function. JSON.stringify skips undefined, functions and Symbols.
Can you have dynamic keys with an object literal?

Yes, with computed property names: { [expr]: value }, where expr is any expression evaluated at creation time. You can also assign later with obj[expr] = value.

How do you add read-only properties?

Object.defineProperty with writable: false, a getter with no setter, or Object.freeze for the whole object. In strict mode writes throw TypeError; otherwise they fail silently.

What is property value shorthand?

When the key name equals the variable name, write it once: { name, age }. Method shorthand { greet() {} } is the sibling feature.

Output of the obj / obj1 snippet and why?

"Second". Objects are reference types; assignment copies the reference, so both names point to one object. Primitives would be copied by value instead.

How do you clone an object? Shallow vs deep?

Shallow: spread or Object.assign (nested objects still shared). Deep: structuredClone (best built-in), a library like lodash cloneDeep, or JSON round-trip with its data-loss caveats.

Object.freeze vs const?

const stops reassigning the variable; freeze stops changing the object's own properties (shallowly). Use both for constants; deep-freeze recursively for nested data.

How do you check if an object is empty?

Object.keys(o).length === 0 (also check o.constructor === Object if needed). if (o) is always true for objects.

How do you loop over an object's properties?

Object.entries(o) with for...of or forEach (best), Object.keys, or for...in with Object.hasOwn. Plain objects are not iterable.

2. The this keyword

this is decided by how a function is called, not where it is defined (except arrow functions, which take it from where they are defined). Rules, in priority order:

#Call stylethis is
1new Fn()the newly created object
2fn.call/apply/bind(ctx)ctx (explicit)
3obj.fn()obj (the thing before the dot)
4fn() plain callglobal object (window) in sloppy mode; undefined in strict mode, modules and class bodies
-arrow functionthis of the enclosing scope (lexical); cannot be changed
function test() { console.log(this) }
test();   // browser, non-strict script: the Window object
          // "use strict" / ES module / class code: undefined
          // Node module: globalThis in sloppy, undefined in strict

const obj = { test: () => { console.log(this) } };
obj.test();   // Window (browser script): the arrow has no this, so it uses the outer (global) this
              // ES module: undefined; Node CommonJS: {} (module.exports)

const user = { name: "Asha", hi() { return this.name } };
user.hi();             // "Asha"  (implicit binding)
const lost = user.hi;
lost();                // "" in browser (window.name), undefined in Node/strict: this was lost
setTimeout(user.hi, 0);// same loss: callbacks get detached
setTimeout(() => user.hi(), 0);   // fixed with arrow wrapper
setTimeout(user.hi.bind(user), 0);// fixed with bind

Common cases

  • Event handler (regular function): this is the element (event.currentTarget). Arrow handler: outer this.
  • Nested regular function inside a method gets its own (lost) this; use an arrow function, const self = this, or bind.
  • Class methods lose this when passed as callbacks; fix in constructor with bind or use a class-field arrow function (React class components).
  • Top-level this: window in a classic script, undefined in an ES module.
const o = { n: "o",
  regular() { return [1].map(function () { return this }) },    // [window] or [undefined]
  arrow()   { return [1].map(() => this) }                       // [o]
};
const counter = { count: 0, inc() { this.count++ } };
const { inc } = counter; inc();   // sloppy: NaN set on window; strict: TypeError
Trap: an arrow function as an object method ({ f: () => this.x }) never sees the object. Object literal braces do not create a scope or a this. Also this in function(){} callbacks of forEach is lost unless you pass the thisArg: arr.forEach(fn, ctx).
What will test() print in the browser and why?

The window object: a plain call uses default binding, which is the global object in non-strict code. In strict mode or an ES module it prints undefined.

What is this inside an arrow function? Output of obj.test()?

Arrows have no own this; they capture it lexically from the surrounding scope at definition. Here the surrounding scope is the global scope, so it prints window (browser script) rather than obj.

Explain this in the global scope, a method, a constructor, an event handler.

Global: window/undefined (module). Method: the owning object. Constructor: the new instance. Handler: the DOM element (regular function) or lexical this (arrow).

3. call(), apply() and bind()

All three set this explicitly for a function. They live on Function.prototype.

Invokes now?ArgumentsReturns
fn.call(ctx, a, b)yeslisted one by onefn's result
fn.apply(ctx, [a, b])yesone array (or array-like)fn's result
fn.bind(ctx, a)nopre-filled (partial application)a NEW bound function
function intro(greet, p) { return `${greet} ${this.name}${p}` }
const a = { name: "Asha" };
intro.call(a, "Hi", "!");         // "Hi Asha!"
intro.apply(a, ["Hi", "!"]);      // "Hi Asha!"
const f = intro.bind(a, "Hello"); // new function, this = a, greet pre-filled
f("?");                           // "Hello Asha?"

// method borrowing and array-likes
Array.prototype.slice.call(arguments);
Math.max.apply(null, [3, 9, 2]);  // 9 (today: Math.max(...arr))
const bound = f.bind({ name: "Other" }); bound("!"); // still "Hello Asha!": bind is permanent

const obj = { a: 6 };
function test() { this = obj; }   // SyntaxError: Invalid left-hand side in assignment
test();                           // never runs: it is an early error at parse time

Polyfill (very common machine-coding question)

Function.prototype.myCall = function (ctx = globalThis, ...args) {
  const key = Symbol();            // avoid overwriting existing props
  ctx[key] = this;                 // this = the function being called
  const res = ctx[key](...args);
  delete ctx[key];
  return res;
};
Function.prototype.myBind = function (ctx, ...pre) {
  const fn = this;
  return function (...post) { return fn.apply(ctx, [...pre, ...post]) };
};
Trap: this cannot be assigned (it is not a variable); the only ways to set it are new, call/apply/bind and the call site. Arrow functions ignore the ctx passed to call/apply/bind (but bind still pre-fills args). A bound function ignores later binding; with new, the bound ctx is ignored too.
Difference between call, apply and bind?

call and apply invoke immediately (arguments listed vs array: "Comma vs Array"); bind returns a new function with this (and optionally leading arguments) fixed, to be called later.

Can you assign this with =?

No. this = obj is a SyntaxError (Invalid left-hand side in assignment) raised before any code runs.

When would you use bind in practice?

Passing methods as callbacks (event handlers, timers, React class components), partial application (multiply.bind(null, 2)), and fixing this for borrowed methods.

4. Classes, class expressions and static members

A class (ES6) is syntactic sugar over prototype-based inheritance: typeof Class === "function", methods live on Class.prototype, and instances are linked to it.

class Person {
  species = "human";        // public instance field (per instance)
  #ssn;                     // private field: only accessible inside the class
  static count = 0;         // static field

  constructor(name, ssn) {  // runs automatically on `new Person(...)`; only one allowed
    this.name = name; this.#ssn = ssn; Person.count++;
  }
  greet() { return `Hi ${this.name}` }       // on the prototype, shared
  #secret() { return this.#ssn }             // private method
  static create(n) { return new this(n) }    // static factory
  static { /* static initialisation block (ES2022) */ }
}
const p = new Person("Asha", 123);
p.greet();  p.#ssn;   // SyntaxError outside the class
Person();              // TypeError: Class constructor Person cannot be invoked without 'new'
typeof Person;         // "function"

Rules to remember

  • Class declarations are hoisted but in the TDZ (new A(); class A {} throws ReferenceError), unlike function declarations.
  • Class bodies are always in strict mode. Methods are non-enumerable (don't show in for...in).
  • No constructor written = default constructor(){} (derived classes: constructor(...args){ super(...args) }). If a constructor returns an object, that object replaces the instance.
  • Arrow function class fields (handle = () => {...}) are per-instance copies with bound this; normal methods are shared on the prototype.

Dynamic names and class expressions

const m = "greet", k = "id";
class A { [m]() { return "hi" }  static [`make_${k}`]() {}  get [k]() { return 1 } }
new A().greet();                 // "hi" (computed method names)

const B = class { };             // anonymous class expression; B.name === "B"
const C = class Inner { who() { return Inner.name } };  // Inner visible only inside
new (class { x = 1 })().x;       // 1 (anonymous, instantly used)
const Mixin = Base => class extends Base { fly() {} };  // class factory (mixin)

Static members

Belong to the class itself, not to instances (instance.staticFn is undefined). Use for utilities, factories, constants, counters and caches shared across instances. Subclasses inherit statics.

class MathX {
  static PI = 3.14159;
  static square(x) { return x * x }
  static cube(x) { return x * this.square(x) }      // static -> static: use this or MathX.
  area(r) { return MathX.PI * MathX.square(r) }      // instance -> static: use ClassName or this.constructor
}
MathX.cube(3);  // 27     new MathX().square // undefined
Trap: this inside a static method is the class, so const f = MathX.cube; f(2) loses it (this = undefined). Class fields are initialised before the constructor body in base classes, but after super() in derived ones. Private fields are truly private (not _name convention), and JSON.stringify ignores them.
How can you create a class? When is constructor() called?

class Name { constructor(){} method(){} }. The constructor runs exactly once per new, before the instance is returned; it initialises instance state.

Can you have dynamic property or method names?

Yes, computed names with brackets for methods, accessors and static members: [expr]() {}.

What is a class expression?

A class defined inside an expression, named or anonymous, assignable to a variable or returned from a function. A name on it is only visible inside the class body.

What are static members and why use them?

Properties and methods on the constructor itself, shared and callable without an instance (Array.isArray, Object.keys, Promise.all are static). They keep helpers and shared state with the class.

How do you call another static method?

Inside static code use this.other() or ClassName.other(); from instance code use ClassName.other() or this.constructor.other().

Class vs constructor function? Are classes real?

Classes add enforced new, strict mode, non-enumerable methods, TDZ, private fields and clean extends/super. Under the hood both use prototypes.

5. Inheritance, subclassing and extending built-ins

class Animal {
  constructor(name) { this.name = name }
  speak() { return `${this.name} makes a sound` }
  static kingdom() { return "Animalia" }
}
class Dog extends Animal {            // subclassing
  constructor(name, breed) {
    super(name);                      // MUST come before any use of this
    this.breed = breed;
  }
  speak() { return super.speak() + ": Woof" }   // override and reuse parent logic
}
const d = new Dog("Rex", "Lab");
d.speak();              // "Rex makes a sound: Woof"
Dog.kingdom();          // "Animalia" (statics inherited)
d instanceof Dog, d instanceof Animal;   // true true
Object.getPrototypeOf(Dog.prototype) === Animal.prototype;  // true
  • extends sets up two chains: Dog.prototype → Animal.prototype (instances) and Dog → Animal (statics).
  • super(...) calls the parent constructor; in a derived class, accessing this before it throws ReferenceError. super.method() calls the parent version; works in static methods too.
  • Overriding = defining a method with the same name in the subclass. Property lookup walks the prototype chain until found, then null.
  • A class can extend only one class (no multiple inheritance). Combine behaviours with mixins or favour composition (has-a) over inheritance (is-a).

Extending built-ins

class Stack extends Array {
  peek() { return this[this.length - 1] }
}
const s = new Stack(); s.push(1, 2);
s.peek();                  // 2
s.length;                  // 2 (length behaves correctly)
s.map(x => x) instanceof Stack;   // true (Symbol.species creates the same subclass)

class AppError extends Error {
  constructor(msg, code) { super(msg); this.name = "AppError"; this.code = code }
}
try { throw new AppError("Boom", 500) } catch (e) { e instanceof AppError, e instanceof Error, e.stack }

class DefaultMap extends Map { get(k) { return super.has(k) ? super.get(k) : 0 } }

Pre-ES6 (prototype) inheritance, still asked

function Animal(name) { this.name = name }
Animal.prototype.speak = function () { return this.name };
function Dog(name) { Animal.call(this, name) }              // inherit instance props
Dog.prototype = Object.create(Animal.prototype);             // link chain
Dog.prototype.constructor = Dog;                             // repair constructor
const o = Object.create(proto);   // create an object directly from a prototype
Trap: forgetting super() in a derived constructor throws "Must call super constructor". Arrow-function methods (fields) are NOT on the prototype, so super.method() can't reach them. Extending built-ins in old transpiled code (Babel ES5) broke instanceof. Object.create(null) makes an object with no prototype (useful as a pure dictionary).
How do you inherit a class? What is subclassing?

Use class Child extends Parent. Subclassing is creating a specialised class that reuses and extends another class's behaviour.

What is the purpose of super?

As a function (super(args)) it calls the parent constructor and creates this; as an object (super.m()) it accesses parent methods and statics, enabling overriding with reuse.

How do you override a method? Extend a built-in?

Redefine it with the same name in the child (call super.name() to keep parent behaviour). Built-ins like Array, Error, Map and Promise can be extended with extends and a super() call.

Explain the prototype chain and __proto__ vs prototype.

prototype is a property of constructor functions/classes, used as the template for instances. __proto__ (use Object.getPrototypeOf) is each object's internal link to its parent. Lookups walk that link chain to Object.prototype then null.

6. Object destructuring

Unpacks properties by name (order does not matter) into variables.

const user = { id: 1, name: "Asha", address: { city: "HYD", pin: 500001 }, tags: ["a", "b"] };
const { id, name } = user;                         // basic
const { name: userName } = user;                   // rename -> userName
const { role = "guest" } = user;                   // default (only when undefined)
const { address: { city } } = user;                // nested (address itself is NOT a variable)
const { id: uid, ...others } = user;               // rest collects remaining props
const { [key]: val } = user;                       // computed key
const { tags: [firstTag] } = user;                 // mix with array destructuring
let x; ({ x } = { x: 5 });                         // assignment form needs parentheses

const { a = 90, b } = {};
console.log(a, b);         // 90 undefined
const { c = 1 } = { c: null };   // c = null (null does not trigger the default)
const { length } = "hello";      // 5 (works on primitives)
const { z } = null;              // TypeError: Cannot destructure property 'z' of null

// function parameters
function render({ title, size = 12, theme: { dark = false } = {} } = {}) {}
render({ title: "Hi" });
const Component = ({ name, age }) => `${name} ${age}`;          // React props pattern
const { data, error } = await fetchUser();                       // API response
const { type, payload } = action;                                // Redux action
for (const { id, name } of users) {}                             // in loops
const { [dynamicKey]: removed, ...withoutIt } = obj;             // immutably omit a key
Trap: { a } = obj at statement start is parsed as a block, so wrap in parentheses. Defaults only replace undefined. A nested default needs both levels ({ a: { b } = {} }) or destructuring a missing parent throws. Rest must be last and gives a shallow copy.
Practical scenario for object destructuring?

Reading API responses (const { data, status } = res), named function options with defaults (function f({ retries = 3 })), React props/hooks, importing named exports, and omitting properties with rest.

Output of const { a=90, b } = { }?

90 undefined: a uses the default because the property is missing; b has no default, so undefined.

7. Class accessors: getters and setters

Accessor properties run a function when read (get) or written (set) but look like normal properties. Used for computed values, validation, encapsulation and read-only data.

class Temp {
  #c = 0;
  get fahrenheit() { return this.#c * 9 / 5 + 32 }     // t.fahrenheit (no parentheses)
  set fahrenheit(f) {                                   // t.fahrenheit = 212
    if (typeof f !== "number") throw new TypeError("number required");
    this.#c = (f - 32) * 5 / 9;
  }
  get celsius() { return this.#c }                      // getter only = read-only
}
const t = new Temp(); t.fahrenheit = 212; t.celsius;    // 100
t.celsius = 5;                                          // ignored (TypeError in strict mode/class code)

const o = { _n: 1, get n() { return this._n }, set n(v) { this._n = v } };   // literal accessors
Object.defineProperty(o, "x", { get() { return 1 }, enumerable: true });
  • Getters/setters live on the prototype, are not own properties, and don't show in JSON.stringify of a class instance (but do for object-literal getters).
  • Setter takes exactly one parameter. Use a different backing name (_n, #n) or you get infinite recursion.
  • A getter is recomputed on each read; cache if it is expensive.
What is a getter or setter method?

Special methods defined with get/set that intercept property reads and writes, allowing computed or validated properties with plain property syntax.

What happens if you have a getter but no setter?

The property is read-only; writes are silently ignored in sloppy mode and throw TypeError in strict mode and classes.

8. Map

A Map is a collection of key/value pairs where keys can be any type (objects, functions, NaN) and insertion order is remembered.

const m = new Map([["a", 1], ["b", 2]]);
m.set("c", 3).set({ id: 1 }, "obj");   // set returns the map: chainable
m.get("a");        // 1 (missing key: undefined)
m.has("b");        // true
m.delete("b");     // true (boolean: was it there?)
m.size;            // property, not method
m.clear();         // remove everything

// iteration (insertion order)
for (const [k, v] of m) {}              // default iterator = entries()
for (const k of m.keys()) {}            // keys(), values(), entries()
m.forEach((value, key) => {});          // note: value first, key second
[...m]; Array.from(m.values());

// conversion
const map = new Map(Object.entries({ x: 1, y: 2 }));   // object -> Map
const obj = Object.fromEntries(map);                    // Map -> object (keys become strings)
const arr = [...map];                                   // [["x",1],["y",2]]

// not an entry!
const mm = new Map();
mm["key"] = "value";     // sets a regular PROPERTY on the Map object
mm.size; mm.get("key");  // 0 undefined, use mm.set("key", "value")

const keyObj = {}; const w = new Map([[keyObj, 1]]); w.get(keyObj);  // 1 (by reference)
w.get({});                                                           // undefined
new Map([[NaN, "n"]]).get(NaN);                                      // "n"

Trap: Map.prototype.forEach callback is (value, key), the reverse of what you may expect. m.get(obj) needs the same reference. Object.fromEntries(map) stringifies keys and later duplicates win. Map has no map/filter; spread to an array first: new Map([...m].filter(([k, v]) => v > 1)).
Advantages of Map over objects?

Any key type, guaranteed insertion order, direct iteration, a real size, no prototype key collisions, and better performance for frequent additions and removals. Use objects for fixed-shape records and JSON data.

How do you iterate over a Map?

for...of (entries), keys(), values(), entries(), or forEach((v, k) => ...).

Can you use map['key'] = value? Why?

Syntactically yes, but it creates an ordinary property on the Map object instead of an entry: size stays 0, get/has don't see it, and it isn't iterated. Use set.

Object to Map and Map to object? Remove an item or all items?

new Map(Object.entries(obj)) and Object.fromEntries(map). map.delete(key) removes one (returns boolean), map.clear() removes all.

Practical uses?

Frequency counters, caching/memoisation keyed by object or argument, grouping, LRU cache (insertion order + delete/set to refresh), associating metadata with DOM nodes.

9. Set

A Set stores unique values of any type in insertion order. Equality uses SameValueZero (NaN equals NaN, objects compare by reference).

const s = new Set([1, 2, 2, 3, NaN, NaN]);   // {1,2,3,NaN}
s.add(4).add(1);        // chainable; duplicate ignored
s.has(2);               // true  (O(1), faster than array.includes)
s.delete(2);            // true  removes a specific value
s.size; s.clear();
new Set([{}, {}]).size; // 2 (different references)

[...s]; Array.from(s); for (const v of s) {}  s.forEach(v => {});
const unique = [...new Set([1, 1, 2])];       // dedupe array: [1,2]
[...new Set("hello")].join("");               // "helo"

// entries() returns [value, value] pairs; keys() is the same as values()
new Set(["a"]).entries().next().value;        // ["a", "a"]
Set.prototype.keys === Set.prototype.values;  // true

// set operations
const A = new Set([1, 2, 3]), B = new Set([2, 3, 4]);
const union = new Set([...A, ...B]);
const inter = new Set([...A].filter(x => B.has(x)));      // {2,3}
const diff  = new Set([...A].filter(x => !B.has(x)));     // {1}
// newer engines: A.union(B), A.intersection(B), A.difference(B), A.isSubsetOf(B) (check support)
Trap: Set has no index or get; you can't read s[0]. Objects with equal content are not duplicates, so dedupe objects by a key using a Map. Mutating a Set while iterating can revisit or skip values.
Difference between Map and Set?

Map holds key/value pairs (keys unique); Set holds only unique values. Both keep insertion order, are iterable, and use SameValueZero equality. Set is for membership and uniqueness; Map for lookups by key.

How do you remove specific values? What does entries() return?

set.delete(value) returns a boolean. entries() returns an iterator of [value, value] arrays (to mirror Map's API).

Remove duplicates from an array, and find common elements?

[...new Set(arr)]; common elements: filter one array by setOfOther.has, O(n+m).

10. WeakMap and WeakSet

Like Map and Set but they hold their keys/values weakly: if nothing else references the object, the garbage collector may remove the entry automatically.

const wm = new WeakMap();
let el = { id: 1 };
wm.set(el, { clicks: 0 });  // key must be an object (or non-registered Symbol)
wm.get(el); wm.has(el); wm.delete(el);
wm.set("str", 1);           // TypeError: invalid value used as weak map key
el = null;                  // the entry becomes collectable

const visited = new WeakSet();
function walk(node) { if (visited.has(node)) return; visited.add(node); /* ... */ }   // cycle-safe traversal

// private data and memoisation without leaks
const priv = new WeakMap();

Difference between Map and WeakMap?

Map keys can be any type and are strongly held, so entries stay until deleted; it is iterable with size. WeakMap keys must be objects and are weakly held, so entries vanish when the key is otherwise unreachable; it is not iterable and has no size or clear. This avoids memory leaks when caching per-object data.

Difference between Set and WeakSet?

Same idea: WeakSet holds only objects, weakly, with just add/has/delete, and cannot be iterated or sized. Use it to tag/track objects (visited, branded) without preventing their collection.

Why can't you iterate a WeakMap?

Contents depend on when the GC runs, so exposing them would make program behaviour non-deterministic and would require holding strong references.
